# Flipkiln contract decisions

The normative API is `openapi.yaml`. Application and management paths are rooted at `/api`. JSON errors are `{ "error": { "code": "...", "message": "...", "issues"?: [{"path":"/entries/0/defaultValue","message":"..."}] } }`. An issue path is a JSON Pointer. All mutations with a body use JSON. Administrative auth is an opaque `flipkiln_session` cookie (HTTP-only, SameSite=Strict, Secure in HTTPS deployments). Application auth is `Authorization: Bearer <token>` and never confers management permissions. Do not log token, password or evaluation context.

- `POST /api/auth/login` `{username,password}` → `{username}` with cookie, `GET /api/auth/session` → `{username}`, `POST /api/auth/logout` `{}` → 204. Browser requests include same-origin cookies.
- `GET /api/manage/projects` → `{projects:[{id,name,role,environments:["development","production"]}]}`. `POST /api/manage/projects` `{id,name}` → project with empty rev 1 per environment (bootstrap/global admin). Initial project is `workshop`, display name `Workshop`. Cumulative project roles are `viewer`, `editor`, `publisher`, `admin`. `GET /api/manage/projects/{project}/members` → `{members:[{username,role}]}` and `PUT .../members/{username}` `{role}` → `{username,role}` (role `null` removes membership). Admin only. Seed dev accounts are admin, editor, publisher, viewer and each has its named role on `workshop`. Outside demo mode only configured bootstrap admin is seeded. No public registration.
- Below, management base is `/api/manage/projects/{project}/environments/{environment}` and client base is `/api/client/projects/{project}/environments/{environment}`. Management operations check the project role, including the bootstrap administrator’s implicit admin role. Client tokens are individually revocable and bound to the pair.
- `GET {manage}/state` → `{draftVersion,entries,active:{revision,entries}}`. `PUT {manage}/draft` `{draftVersion,entries}` → same state; stale version returns 409 `draft_conflict`. Each successful write advances the version. Editor+. `POST {manage}/validate` `{entries}` → `{valid,issues}`. Editor+. `POST {manage}/preview` `{entries,keys,context,expectedTypes?}` → `{results:[{key,value?,reason,ruleId?}]}`. Editor+. Preview validates entries first; invalid input → 422.
- `GET {manage}/releases` → `{releases:[{revision,kind,sourceRevision,createdAt,actor,note}]}` newest first. `kind` is `initial`, `publish`, or `rollback`. `sourceRevision` nullable. `GET {manage}/releases/{revision}` → release metadata plus `entries`. History doubles as publication audit. `POST {manage}/publish` `{draftVersion,note}` and `POST {manage}/rollback` `{revision,draftVersion,note}` require `Idempotency-Key` header (unique per actor and environment); both return `{revision,entries}` with 200. Stale versions → 409. Replay returns the original response, including after later releases, and reuse with different parameters → 409 `idempotency_conflict`. Both advance draftVersion; publish keeps matching entries, rollback replaces the draft with the target snapshot. UI shows a computed diff and confirms the environment, and warns that rollback replaces the draft.
- `GET {manage}/tokens` → `{tokens:[{id,name,createdAt,revokedAt}]}`. `POST {manage}/tokens` `{name}` → `{id,name,createdAt,revokedAt,token}` with 201; secret shown once. `DELETE {manage}/tokens/{id}` → 204. Admin only.
- `GET {client}/snapshot` → `{revision,entries}` with quoted `ETag`, honors `If-None-Match` / 304 after token auth. `POST {client}/evaluate` `{keys,context,expectedTypes?}` → `{revision,results}`. Context is `{id?:string,attributes?:Record<string,boolean|string|number|null>}`. `GET /health/live` checks process, `GET /health/ready` checks PostgreSQL and schema.

An entry is `{key,description,type,defaultValue,enabled,rules,schema?}`. Types `boolean`, `string`, `number`, `json`. Keys are lowercase `[a-z][a-z0-9_.-]{0,63}` and unique per snapshot. Use an immutable key and type across versions, including after removal. Changing identity or type requires a new key in that environment. Removing an entry from the draft removes it from client output only on publish. Disabled entries return their default; disabled is distinct from a boolean value of false. Rule value has the entry's type and passes its JSON schema. Rules, in order, are `{id,kind:"ids",ids:[...],value}`, `{id,kind:"attribute",attribute,equals,value}`, `{id,kind:"rollout",percentage,value}`. Rollout uses FNV-1a 64-bit over UTF-8 of `project + "\n" + environment + "\n" + key + "\n" + ruleId + "\n" + id`, `hash % 10000 < percentage * 100`, with integer percentages from 0 to 100. No id skips rollout even at 100. Reason is `disabled`, `rule_match`, `default`, `unknown_key`, or `type_mismatch`. Unknown entries omit value. Clients may pass an `expectedTypes` map from key to entry type to get `type_mismatch` without a value when their expected type differs. Preview and application evaluation share the algorithm. JSON schemas use an explicitly supported Draft 7 subset documented by the API implementation; reject unsupported keywords with field paths. Use the sample fixture for acceptance, and enable it with `FLIPKILN_DEMO=true` only. Use a dedicated database for demo installations. PostgreSQL-backed JSON strings and names cannot contain U+0000. Integer values must be within ±9,007,199,254,740,991 to round-trip through the console.

Infrastructure interface: API image builds at repository context with `apps/api/Dockerfile`, listens on 8080, and uses `/usr/local/bin/flipkiln-api migrate` for migrations. Environment `DATABASE_URL` (libpq PostgreSQL connection string), `FLIPKILN_ADMIN_PASSWORD` (bootstrap, 12–256 bytes), `FLIPKILN_DEMO` (default false), `FLIPKILN_DEMO_PASSWORD` (fixture accounts, 12–256 bytes, defaults to `flipkiln-local-demo`), `FLIPKILN_COOKIE_SECURE` (default true), `FLIPKILN_DEMO_TOKEN` (optional seeded workshop/development token, 20–256 bytes). Run the API as `FLIPKILN_API_MODE=control` (default) for management routes and `FLIPKILN_API_MODE=runtime` for client routes. The runtime process uses its own database credential with execute permission on the published snapshot function. Set `FLIPKILN_RUNTIME_ROLE` on the migration Job to grant that permission. Bootstrap account name `admin`. Local fixtures use `flipkiln-local-demo` and `flipkiln-local-demo-read-token`.
